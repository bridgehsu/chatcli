# 重启与持久化恢复

## 目标

验证 Agent Session、目录选择和待确认 Shell 命令在进程重启后不会丢失或误路由。

## A. 等待工作目录时重启

1. 发送 `/reset`。
2. 发送 `CodeX`，等待“请发送工作目录”。
3. 停止 ChatCLI 进程，再重新启动。
4. 发送一个存在的工作目录路径。

### 预期结果

- 重启后仍处于“等待选择目录”。
- 目录路径被作为目录输入处理，而不是 Agent 聊天或 Shell 输入。
- CodeX 在指定目录启动成功，或在未安装时返回明确错误。

## B. 等待 Shell 确认时重启

1. `/reset` 后发送 `打开终端`。
2. 发送 `查看当前目录`，等待候选命令。
3. 不发送确认，直接重启 ChatCLI。
4. 发送 `帮助`，再发送 `确认`。

### 预期结果

- 帮助提示当前有 Shell 命令等待确认。
- “确认”执行重启前保存的那条候选命令，而不是把“确认”发送给 zsh。
- 发送“取消”则不执行任何命令。

## C. 活动终端时重启

1. 启动 Shell、CodeX 或 Cursor 终端。
2. 重启 ChatCLI，但不要关闭 tmux。
3. 发送 `终端列表`，然后发送一条符合当前终端类型的输入。

### 预期结果

- 终端仍显示为运行中且可切换。
- Shell 能接收 `$ pwd`；CodeX / Cursor 能接收普通任务文本。
- 若 tmux 在重启期间被关闭，终端应被标记为“已失效”。

## 数据检查

测试后可只读检查：

```bash
ls -la ~/.chatcli
```

预期存在 `agent-sessions.json`、`agent-messages.jsonl` 和 `sessions.json`。不要提交这些本地运行数据。
